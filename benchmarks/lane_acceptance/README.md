# Lane acceptance dataset

This directory contains a fixed 100-frame acceptance set from
`test_data/test_video.mp4`, a human annotation UI, and a model-independent
evaluator. It is standalone benchmark code and does not import or modify the
live perception pipeline.

The images and scene strata are ready. Lane labels in `dataset.json` start with
`review_status: "pending"`; they are intentionally not generated by a model.
The evaluator refuses to score models until all 100 records pass the annotation
validator.

## Selection

The 83-second, 24 FPS video has 2,000 reliably decodable frames. Candidate
frames were reviewed on contact sheets at 10-frame intervals. Moving sections
are sampled more often, while the nearly stationary traffic sequence is sampled
more sparsely. The final IDs have a minimum 10-frame gap (0.417 seconds), and
visually redundant adjacent candidates were removed. Exact IDs are stored in
`dataset.json` and fixed in `build_dataset.py`.

Primary selection strata are exact:

| Primary stratum | Frames |
|---|---:|
| Clear normal lane | 20 |
| Intersection | 15 |
| Parked cars / curb heavy | 15 |
| Crosswalk / stop line | 10 |
| Faded lane | 10 |
| Unmarked road | 10 |
| Turning / curved road | 10 |
| Occlusion | 10 |

`selection_stratum` records the primary bucket. `scene_type` is a list because
a frame may also be, for example, both a turn and an intersection. Scene tags
can be corrected in the annotation UI without changing the fixed selection.

Rebuilding is normally unnecessary. If the images are missing, run:

```bash
python benchmarks/lane_acceptance/build_dataset.py
```

The builder refuses to overwrite an existing `dataset.json` unless `--force`
is supplied, protecting manual work.

## Ground-truth format

Every item contains source identity, editable scene tags, review state, an ego
lane decision, and two boundaries:

```json
{
  "frame_id": 480,
  "timestamp": 20.0,
  "image": "frames/frame_0480.jpg",
  "selection_stratum": "clear_normal_lane",
  "scene_type": ["clear_normal_lane"],
  "review_status": "complete",
  "ego_lane_status": "valid",
  "annotation_flag": null,
  "left_boundary": {
    "status": "visible",
    "points": [[438, 697], [501, 560], [543, 455]]
  },
  "right_boundary": {
    "status": "visible",
    "points": [[887, 701], [760, 552], [690, 452]]
  },
  "notes": ""
}
```

Allowed ego statuses are `valid`, `invalid`, and `ambiguous`. Allowed boundary
statuses are `visible`, `not_visible`, and `ambiguous`. Points are integer image
coordinates in the original 1152x720 frame. Click points in boundary order;
bottom-to-top is recommended.

An invalid ego lane must be explicit:

```json
{
  "ego_lane_status": "invalid",
  "annotation_flag": "NO_VALID_EGO_LANE",
  "left_boundary": {"status": "not_visible", "points": []},
  "right_boundary": {"status": "not_visible", "points": []}
}
```

Use a conservative policy:

- Mark `valid` only when the ego corridor is trustworthy from visible evidence.
- Mark `ambiguous` when a careful reviewer could reasonably disagree. Models
  are expected to abstain on these frames.
- Mark `invalid` when there is no trustworthy ego lane and use
  `NO_VALID_EGO_LANE`.
- Do not extend boundaries through vehicles or invent paint through an
  intersection.
- Crosswalk stripes and stop lines are not longitudinal lane boundaries.
- Do not use a parked vehicle edge as a boundary. Treat a curb as an ego
  boundary only when it unambiguously defines the drivable corridor.
- Put points only on the visible boundary. The evaluator interpolates between
  points but does not require a fixed point count.

## Annotation UI

Run from the repository root in a graphical desktop session:

```bash
python benchmarks/lane_acceptance/annotate.py
```

Use `--scale 0.6` if the window is too large or `--frame-id 940` to open a
specific selected frame. Progress is atomically saved to `dataset.json` after
every edit and navigation action. Reopening starts at the last visited frame.

Controls:

| Input | Action |
|---|---|
| Left click | Append a point to the active boundary |
| Right click or `Z` | Remove its last point |
| `L` / `R` | Select left or right boundary |
| `V` / `H` / `A` | Mark active boundary visible, not visible, or ambiguous |
| `G` / `X` / `U` | Mark ego lane valid, invalid, or ambiguous |
| `D` | Clear the active boundary |
| `1` through `8` | Toggle the displayed scene tag |
| Space | Validate and mark the current frame complete |
| `E` | Reopen the current frame for editing |
| `,` / `.` | Previous / next frame |
| `Q` or Esc | Save and quit |

`X` automatically records `NO_VALID_EGO_LANE` and clears both boundaries.
Space refuses to complete records with missing statuses, invalid point counts,
out-of-image coordinates, or an inconsistent no-lane marker.

## Prediction format and evaluator

Predictions use the same ego and boundary status vocabulary but omit review and
selection fields:

```json
{
  "schema_version": 1,
  "model": {"name": "my_lane_model", "version": "checkpoint-id"},
  "predictions": [
    {
      "frame_id": 480,
      "ego_lane_status": "valid",
      "left_boundary": {"status": "visible", "points": [[440, 697], [505, 560]]},
      "right_boundary": {"status": "visible", "points": [[883, 701], [758, 552]]}
    }
  ]
}
```

See `predictions.example.json`. Run:

```bash
python benchmarks/lane_acceptance/evaluate.py path/to/predictions.json
```

The command writes JSON and Markdown reports under `reports/`. Missing frame
predictions are treated as abstentions: safe on invalid/ambiguous ground truth,
but misses on valid ground truth. Predictions for unknown frame IDs are listed
in the report and do not affect metrics.

Implemented metrics:

- valid ego-lane detection rate;
- false ego-lane rate over invalid and ambiguous ground truth;
- missed ego-lane rate;
- left and right visible-boundary detection rates;
- left and right boundary mean, median, P95, and P99 x error in image pixels;
- the same boundary errors divided by image width;
- intersection, unmarked-road, crosswalk/stop-line, and parked-car/curb false
  positive rates over tagged invalid/ambiguous frames;
- abstain rate and correct abstain rate;
- a safety-weighted error rate where one false lane costs three missed lanes.

Boundary geometry is evaluated at 50 common y positions over the overlapping
vertical range of each visible ground-truth/prediction pair. A pair with no
vertical overlap receives an image-width error. These are image-space metrics;
the report never interprets them as meters.

Run metric tests with:

```bash
python -m unittest discover -s tests -p 'test_lane_acceptance.py'
```
